# Autonomous Sales Team

Битрикс24 подключён через разрешённый READ ONLY клиент Lead Hunter. Контур поиска и подготовки запускается через очередь SQLite, сохраняет результаты по компании и этапу и возобновляется с незавершённого этапа. Внешняя история CRM в модель и клиентские HTML не передаётся.

## Запуск и управление

Запуск из корня проекта.

```sh
.venv/bin/python -m app.sales_team skills
.venv/bin/python -m app.sales_team simulate
.venv/bin/python -m app.sales_team dashboard
.venv/bin/python -m app.sales_team status
.venv/bin/python -m app.sales_team stop
.venv/bin/python -m app.sales_team resume
```

Панель доступна на `http://127.0.0.1:8792/` во время работы команды `dashboard`. Она читает локальную очередь и готовые файлы. Остановка хранится в БД, действует для планировщика и проверяется между запросами и этапами. Возобновление позволяет рабочему процессу продолжить от последней сохранённой единицы. Внешние письма, звонки и записи в CRM отсутствуют.

Автоматический поиск использует GDELT по Казахстану и региональные публичные ленты, а также явно настроенные публичные индексы и сайты компаний. Режим без предварительно собранного JSON:

```sh
.venv/bin/python -m app.sales_team --source-config data/sales_team/sources.json --previous data/sales_team/previous.json run
```

Проверенное исследование из разрешённых источников можно передать операторским пакетом. Его строки проходят ту же квалификацию и новый READ ONLY поиск совпадений. Источник, дата наблюдения, коммерческая гипотеза и рабочие контакты сохраняются раздельно. Формат — JSON-массив объектов [Prospect](../app/models/sales_team.py).

```sh
.venv/bin/python -m app.sales_team --previous data/sales_team/previous.json run --prospects PUBLIC.json
```

`--model codex` использует уже авторизованный локальный Codex CLI для явно ограниченного числа публичных черновиков (`--model-limit 1` по умолчанию). Команда запускается с пустым рабочим каталогом, отключёнными командами, hooks и веб-поиском, с типизированным форматом ответа. Обработка использует существующую квоту аккаунта. Задача не требует нового API-ключа. При недоступности CLI или невалидном ответе отчёт указывает причину перехода на правила. Установленный планировщик не пользуется квотой модели.

Каждый запуск сохраняется в `outputs/sales_team/<id>/`. `leads.xlsx` и `leads.csv` передаются менеджеру. `index.html` открывает наглядные учебные сценарии, `summary.json` содержит решения, источники, аудит чтения CRM и итог аналитика. У симуляции есть `workflow.json` и `simulation.json`.

## Планировщик macOS

Служба `kz.crmconsulting.sales-team` проверяет очередь каждые 15 минут и ставит новую задачу поиска раз в сутки, пока очередь запущена. Параллельные процессы не обрабатывают один файл состояния одновременно. При закрытом сеансе пользователя или выключенном Mac задания обработаются после возобновления работы. Журнал ОС и приватная БД находятся в `data/sales_team`.

На этом Mac служба запрашивает доступ Python к папке «Документы» при первом старте. До подтверждения системного окна фоновый процесс может ждать и не создать запись запуска. Проверить службу можно командой `launchctl print gui/$UID/kz.crmconsulting.sales-team`.

Воспроизводимая конфигурация создаётся командой:

```sh
.venv/bin/python -m app.sales_team --source-config data/sales_team/sources.json --previous data/sales_team/previous.json schedule-plist
```

## Роли и наблюдения

Восемь SKILL.md лежат в [app/sales_knowledge](../app/sales_knowledge). Пайплайн загружает их версии и контрольные суммы в квитанцию каждого этапа. Требования к минимальному числу источников, шагов демонстрации и объёму наблюдений читаются из соответствующих навыков. Модель получает тексты навыков психологии, маркетинга и коммуникации в публичном запросе. Остальные решения выполняются встроенными правилами, привязанными к этапам.

Реальные результаты можно занести командой `record EVENT.json` с полями `event_id`, `run_id`, `company`, `kind`, `at`, `variant`, `language`, `segment`. Идентификатор должен относиться к конкретному наблюдавшемуся событию. Повтор с тем же содержанием не увеличит счётчик. Симуляция не является наблюдением. Наличие ответа, согласие обсудить показ и подтверждённое бронирование встречи — разные события. Аналитик показывает долю встреч от наблюдавшейся доставки или голосового соединения без автоматической правки правил.

## Границы развёртывания

Открытый публичный индекс может дать ноль подтверждённых новых компаний. Источники, доступные только после CAPTCHA или входа, автоматически не обходятся. Рекламные библиотеки, защищённые вакансии и тендеры могут использоваться как входные проверенные свидетельства. Веб-сборщик не содержит доступов к ним и не обновляет старую проверку без прочтения страницы.

Голосовой компонент формирует двуязычное досье и выполняет тестовый текстовый диалог. Двусторонний аудиомаршрут, автоматическое чтение входящих от провайдера, бронирование во внешнем календаре и исходящий транспорт зависят от утверждённых рабочих доступов. Текущие результаты проверки телефонии и правовые источники описаны в [sales_voice.md](sales_voice.md).
